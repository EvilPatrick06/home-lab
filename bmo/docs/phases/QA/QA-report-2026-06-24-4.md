### `POST /api/lists/<name>/items/<id>/check` returns 415 when the request omits a JSON Content-Type
- **Category:** bug (robustness) | **Severity:** low | **Domain:** bmo | **Discovered by:** QA Agent | **During:** list check endpoint probing
- **Description:** The check handler does `data = request.json or {}` (`app.py:2294`). On a POST with no `Content-Type: application/json`, Flask's `request.json` raises **415 Unsupported Media Type** *before* the `or {}` fallback runs, so the call fails outright instead of defaulting to `{done: true}`. No user impact today — the only caller (`bmo.js:4526`) always sends the JSON header — but it's a brittle contract: any future caller (curl, a tile that toggles "done" without a body, a 3rd-party script) gets a confusing 415 rather than a sensible default. (`/clear` at `app.py:2301` has the same `request.json or {}` shape.)
- **Reproduction:** 1) add a list item; 2) `curl -X POST .../items/<id>/check` (no `-H Content-Type`) → **415**; 3) same call **with** `-H 'Content-Type: application/json' -d '{}'` → **200**.
- **Expected behavior:** Either accept a bodyless check (treat as `done:true`) or return a 400 with a clear message — not a raw 415.
- **Hypothesis / root cause:** `request.json` (non-silent) raises on a non-JSON mimetype; should be `request.get_json(silent=True) or {}`.
- **Suggested action:** Use `request.get_json(silent=True) or {}` in `api_list_check_item` (and `api_list_clear`).
- **Environment:** Pi loopback · fresh backend · single-user.
- **Related files:** `bmo/pi/app.py:2289-2298` (check), `:2301-2310` (clear).
