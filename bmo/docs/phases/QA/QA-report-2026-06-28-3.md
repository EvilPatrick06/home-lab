## 2. Chat tab

### bmo chat agent is unavailable at runtime — every `/api/chat` message fails

- **Category:** bug
- **Severity:** high
- **Domain:** bmo
- **Discovered by:** QA Agent
- **During:** chat tab → sending a message (UI) and `POST /api/chat` (loopback)

**Description:** The bmo home-assistant chat returns no real responses. A live `POST /api/chat` on loopback produced **HTTP 500** with `AttributeError: 'NoneType' object has no attribute 'chat'`. The agent initialised cleanly at process start (journal: `Creating agent... Agent: OK`, `Restored 47 messages into agent history`, `BMO is ready!`), yet at request time `_app().agent` resolves to `None`. In the UI, the chat history is full of `(interrupted — try asking again)` entries from prior probe attempts — the user-visible symptom of the same failure.

**Reproduction:**
1. `curl -s -X POST http://127.0.0.1:5000/api/chat -H 'Content-Type: application/json' -d '{"message":"what is 3+4?","speaker":"unknown"}'`
2. Observe HTTP 500 (live `f51d9dc3`).
3. Server log (`journalctl _PID=259659`): `File ".../routes/chat_api.py", line 59, in api_chat / result = _app().agent.chat(...) / AttributeError: 'NoneType' object has no attribute 'chat'`.

**Expected behavior:** A typed/spoken message returns an assistant reply. If the agent is genuinely unavailable, the endpoint should degrade to a handled `503 {"error":"agent unavailable"}` (the guard master added) **and** the agent should not be `None` in normal operation.

**Hypothesis / root cause:** Module-identity split in `_app()` (`bmo/pi/routes/chat_api.py:24-37`). The process runs as `python app.py`, so services (incl. `agent`) are initialised on `sys.modules['__main__']`. `_app()` returns `__main__` only if `getattr(main,'agent',None) is not None`; otherwise it falls back to `import app`, a **second** module object whose `agent` global was never populated → `None`. The `.chat` call (`chat_api.py:59` live; the guarded path `:56-59` on master) then dereferences that `None`. On master the new guard converts the 500 into a 503, but the agent is still unreachable, so **chat is non-functional on master too** (every turn → "agent unavailable"). The deeper fix is making `_app()` resolve the same initialised module that holds `agent` (or initialising services on the importable `app` module), not just guarding the symptom.

**Suggested action:** Trace why `_app().agent` is `None` at request time despite a successful startup init — most likely the `__main__` vs `import app` duplication; ensure the chat path reads the module where `init_services()` actually populated `agent` (and `voice`). Re-verify with a live `POST /api/chat` after a restart.

**Environment:** LAN/loopback · kiosk off · connected · agent present at boot but `None` at request time · live `f51d9dc3` (500); master `d9dccc65` would 503.

**Related files:** `bmo/pi/routes/chat_api.py` (`_app()` 24-37; `api_chat` guard+call 56-72), `bmo/pi/app.py` (`init_services`), `bmo/pi/agent.py`.

**Console output:** `AttributeError: 'NoneType' object has no attribute 'chat'` (server); browser console clean.

**Screenshot(s):** `screenshots/tab-chat.png`, `screenshots/chat-live-probe.png`

> **Note:** already reported in `completed/QA-report-2026-06-28.md` and `completed/QA-report-2026-06-28-2.md` ("chat-agent agent is None"); **still unresolved**. Not yet triaged into `docs/logs/BMO-ISSUES-LOG.md`.

## 8. IDE tab + /ide

### /ide loads Google Fonts that CSP blocks — console error + failed request on every load

- **Category:** bug
- **Severity:** low
- **Domain:** bmo
- **Discovered by:** QA Agent
- **During:** /ide standalone + IDE tab

**Description:** `web/templates/ide.html:9-10` `preconnect`s and `<link>`s `https://fonts.googleapis.com/css2?family=JetBrains+Mono…&family=Inter…`, but the app's CSP (`app.py:187` `style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net`; `app.py:196` `font-src 'self' data: https://cdn.jsdelivr.net`) does not allow the Google Fonts origins. Result: every `/ide` load logs a CSP violation and a failed `GET` for the stylesheet, and the IDE renders in fallback fonts rather than the intended JetBrains Mono / Inter. The terminal still connects ("Connected") and the editor/file-tree work.

**Reproduction:**
1. Open `http://127.0.0.1:5000/ide`.
2. Console: `Loading the stylesheet 'https://fonts.googleapis.com/css2…' violates the following Content Security Policy directive: "style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net"… blocked.`
3. Network: `GET https://fonts.googleapis.com/css2… :: csp` (failed).

**Expected behavior:** No CSP errors; the IDE either gets its intended fonts or doesn't request blocked ones.

**Hypothesis / root cause:** CSP `style-src`/`font-src` omit `https://fonts.googleapis.com` / `https://fonts.gstatic.com`, while `ide.html` still references Google Fonts.

**Suggested action:** Either add `https://fonts.googleapis.com` to `style-src` and `https://fonts.gstatic.com` to `font-src` in `app.py`, or self-host / serve the fonts from the already-allowed `cdn.jsdelivr.net`, or drop the Google Fonts `<link>` and rely on local fonts.

**Environment:** loopback · /ide standalone and IDE tab · connected.

**Related files:** `bmo/pi/app.py` (CSP 173-200), `bmo/pi/web/templates/ide.html:9-10`.

**Console output:** see Reproduction step 2.

**Screenshot(s):** `screenshots/ide-standalone.png`
