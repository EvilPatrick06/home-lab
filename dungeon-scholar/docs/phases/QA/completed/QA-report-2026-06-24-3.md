## 2 Library & tomes

### New CSV/Quizlet import and Occlusion authoring are unreachable once a tome is active
- **Category:** UX
- **Severity:** medium
- **Domain:** dungeon-scholar
- **Discovered by:** QA Agent
- **During:** Phase 2 library — locating the new "Import Deck (CSV/Quizlet)" and "Author Occlusion Card" features
**Description:** The two new content-creation entry points — **Import Deck (CSV/Quizlet)** and **Author Occlusion Card** — are rendered only in the Home screen's *empty / no-tome-open* state (`HomeScreen.jsx` add-tome button group). They are **not** wired into the Library ("The Grand Library") toolbar, which exposes only Forge with Magic, Paste Tome Text, Import Share Code, and Inscribe a Tome. Because the app has **no affordance to close/deselect the active tome** (an `activeTomeId` only becomes null via `defaultState`/deleting every tome), any returning user who already has a tome loaded — i.e. the normal steady state — has **no path** to the CSV/Quizlet importer or the occlusion authoring tool short of deleting all their tomes. These are headline new features (commits 9b5d93a6, 0070472f) that most users will never find.
**Reproduction:**
1. Load the app with at least one tome active (the default returning-user state).
2. Home screen: only the dashboard shows (active tome + study modes); no import buttons.
3. Go to Library: toolbar has Forge / Paste / Import Share Code / Inscribe a Tome — no "Import Deck (CSV/Quizlet)" and no "Author Occlusion Card".
4. There is no button anywhere to unload the active tome to return to the Home empty-state where those two live.
**Expected behavior:** The CSV/Quizlet import and Occlusion authoring actions should also be available from the Library add-tome toolbar (and/or a persistent "+ Add tome" menu), so they're reachable regardless of active-tome state.
**Hypothesis / root cause:** `LibraryScreen.jsx` toolbar (~lines 205-235) wires only `onPaste`/`onImportCode`/Forge/Inscribe; it never receives or renders `onImportDeck` / `onAuthorOcclusion`. Those handlers (`App.jsx:1097-1098`) are only consumed by `HomeScreen.jsx`'s empty-state button group, which is hidden whenever a tome is open.
**Suggested action:** Add "Import Deck (CSV/Quizlet)" and "Author Occlusion Card" to the Library toolbar (pass `onImportDeck`/`onAuthorOcclusion` into `LibraryScreen`), or provide a global "Add tome" menu containing all six import methods.
**Environment:** signed-in · Dark · active tome loaded
**Related files:** `dungeon-scholar/src/features/library/LibraryScreen.jsx`, `dungeon-scholar/src/features/home/HomeScreen.jsx:148-165`, `dungeon-scholar/src/App.jsx:1097-1098`

### CSV/Quizlet import: whole-file tab-priority delimiter detection silently drops comma rows when any line contains a tab
- **Category:** bug
- **Severity:** low
- **Domain:** dungeon-scholar
- **Discovered by:** QA Agent
- **During:** Phase 2 — Import Deck (CSV/Quizlet) with a deck mixing comma rows and one tab-separated row
**Description:** `detectDelimiter()` chooses the delimiter for the **entire** file: if any of the first 10 lines contains a tab, the whole input is parsed as TSV. A deck of three comma rows plus one tab row imported only the single tab row ("Imported 1 card from Quizlet/TSV") — the two comma rows were silently dropped (parsed as one untab-split field with no back). The same hazard hits a legitimate CSV whose first 10 lines contain a stray tab character (e.g. a tab inside a definition): most rows would be misparsed and dropped. The only feedback is the low count in the success toast; nothing warns the user that N rows were skipped. (Pure-CSV and pure-TSV inputs both import correctly — this only affects mixed / embedded-tab content.)
**Reproduction:**
1. Empty library -> Home -> Import Deck (CSV/Quizlet).
2. Paste: `What is 2+2?,Four` / `Capital of France,Paris` / `mitochondria\tpowerhouse of the cell` (the last line tab-separated).
3. Convert & Inscribe -> toast: "Imported 1 card from Quizlet/TSV"; only the tab row is imported.
**Expected behavior:** Either detect the delimiter per-line, or warn when rows are dropped/unparseable ("2 of 3 rows could not be parsed"), so import isn't silent partial data loss.
**Hypothesis / root cause:** `src/services/deckImport.js` `detectDelimiter()` = `sample.includes('\t') ? '\t' : ','` over the first 10 lines — a whole-file, tab-priority choice; `parseDelimited` in tab mode does a plain `line.split('\t')`, so comma rows collapse to a single field and are filtered out as having no back.
**Suggested action:** Detect delimiter per row (or count comma vs tab occurrences and pick the dominant), and surface a "skipped N unparseable rows" notice on import.
**Environment:** signed-out cloud-unreachable · Dark · empty library
**Related files:** `dungeon-scholar/src/services/deckImport.js` (`detectDelimiter`, `parseDelimited`)

_Verified working: **no-tome gate** — after deleting all tomes (`activeTomeId` -> null), the COURSE_SET_GATED screens `#/quiz`, `#/dungeon`, `#/flashcards` all bounce to `#/home`. **Tome deletion** — bulk-Banish of the only tome empties the library and clears the active tome (matches the documented "delete last tome clears active"). **CSV import (primary path)** — a header row (`term,definition,tag`) is auto-detected/skipped, comma rows parse, RFC-style quoted fields (`"5 TB"`) parse, and a 3rd column maps to the card's domain tag (Math/Geography/AWS); "Imported 3 cards from CSV". The empty-state Home correctly exposes all six importers including the two new ones._

### Shop item copy leaks a developer-internal "Phase 14" reference to users
- **Category:** docs
- **Severity:** low
- **Domain:** dungeon-scholar
- **Discovered by:** QA Agent
- **During:** Phase 5 — Shop purchase confirm modal (Shield Draught)
**Description:** The Shield Draught purchase-confirm modal reads "Replenish a single dungeon shield (**used in Phase 14 combat**)." "Phase 14" is an internal development phase number, meaningless to players, and breaks the in-world tone. A second item carries the same leak: the familiars item blurb reads "Familiars to walk the dungeon at thy side. (**Awaiting Phase 18.**)" — exposing an internal roadmap phase to players.
**Reproduction:**
1. Shop -> find Shield Draught (Apothecary) -> Purchase.
2. Read the confirm modal description.
**Expected behavior:** Player-facing copy describes the item in-world (e.g. "Restores one shield for your next dungeon delve") with no internal phase numbers.
**Hypothesis / root cause:** Two item strings in the catalog carry dev-facing phase references: `src/game/items.js:96` (`'Replenish a single dungeon shield (used in Phase 14 combat).'`) and `src/game/items.js:20` (`'Familiars to walk the dungeon at thy side. (Awaiting Phase 18.)'`).
**Suggested action:** Replace "used in Phase 14 combat" with in-world copy; grep the item catalog for other "Phase N" leaks.
**Environment:** signed-in · Dark · shop screen
**Related files:** `dungeon-scholar/src/game/items.js:20,96`
