- **Discovered by:** QA Agent

### Stale persisted session + unreachable host → ~20 console errors on EVERY page load; quarantine never clears the token

- **Category:** bug
- **Severity:** medium
- **Domain:** dungeon-scholar
- **Discovered by:** QA Agent
- **During:** console health on load, signed-in-stale profile, Supabase host unreachable

**Description:** With a stale persisted session (`sb-...-auth-token`, expired 2026-05-19) and the Supabase host unreachable, every page load produces a ~30 s storm of ~20 uncaught `TypeError: Failed to fetch` / `AuthRetryableFetchError` console errors from GoTrue`s internal `_callRefreshToken` exponential-backoff retries. The PHASE-08 08E quarantine (useAuth.js) is supposed to trip after 3 failures, locally sign out (clearing the token), stop the ticker, and log ONE warning. Observed: the UI does drop to signed-out ("Sign in with GitHub to sync" shown), but (a) the token is STILL in localStorage after the storm — verified twice, before and after a reload — so the storm repeats on every load, and (b) no quarantine warning appears in console.

**Reproduction:**
1. Have an expired `sb-*-auth-token` in localStorage while the Supabase host is unreachable (current live state)
2. Load the app; watch console for ~30 s → ~20 fetch errors
3. Check localStorage → token still present; reload → storm repeats identically

**Expected behavior:** Per the code`s own comments: ≤3 failures, token dropped, single `logWarn`, storm never repeats on later loads.

**Hypothesis / root cause:** (speculation) `supabase.auth.signOut({ scope: "local" })` in the `quarantine()` path internally awaits `_useSession`/refresh first; with an expired session and unreachable host that throws `AuthRetryableFetchError` before the storage key is removed, the `catch {}` swallows it, and the token survives. Also the ~20 errors come from GoTrue`s internal retry backoff inside a single explicit refresh call, which useAuth`s `MAX_REFRESH_FAILURES=3` counter never sees as 3 separate failures. `dungeon-scholar/src/hooks/useAuth.js` (quarantine, ~line 60-75), `src/services/supabase.js:15`.

**Suggested action:** In `quarantine()`, remove the `sb-*-auth-token` storage key directly (synchronously) instead of relying on `signOut({scope:"local"})`; consider `fetch` wrapper suppression or a shorter GoTrue retry budget so an unreachable host fails fast and once.

**Environment:** live deploy · stale signed-in session · Supabase host DNS-dead · dark · desktop

**Related files:** `dungeon-scholar/src/hooks/useAuth.js`, `dungeon-scholar/src/services/supabase.js`

**Console output (if any):** 20 errors 12:05:54-12:06:23 (initial load), ~19 more after one reload; stacks end at `jo._refreshAccessToken` / `jo._callRefreshToken`
